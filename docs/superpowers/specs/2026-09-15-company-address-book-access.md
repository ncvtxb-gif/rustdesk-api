# Sweetnight-PC 企业地址簿权限设计

## 目标

建立唯一的企业地址簿 `Sweetnight-PC`：所有受管 Windows 设备在飞书登录成功后自动加入，设备显示名称取最后登录用户的飞书 `nickname`，但地址簿仅管理员可见和管理。

## 身份与字段口径

- `Peer.Username` 是 Windows 系统账号，仅用于设备管理页。
- `User.Nickname` 是飞书用户姓名，是企业地址簿条目的 `AddressBook.Username`。
- 同一设备由其他飞书用户再次登录时，幂等更新该条目的 `Username` 为最后登录用户的 `Nickname`；昵称为空时回退到应用账号 `User.Username`。
- `AddressBookCollection.UserId` 是全局地址簿的技术所有者，继续由系统管理员账号持有，不作为设备归属展示。

## 自动入簿

- 桌面客户端登录和受管设备身份登录均调用 `EnsureCompanyDevice`。
- `Sweetnight-PC` 必须恰好存在一份；缺失或重复时拒绝写入并记录错误，避免设备进入错误地址簿。
- 设备条目以 `(user_id, collection_id, id)` 唯一，重复登录执行 upsert，并刷新飞书姓名、主机名和平台。
- 提供只执行一次的既有设备补录路径，将当前设备按其绑定用户加入全局地址簿。

## 权限

- 管理员对 `Sweetnight-PC` 拥有完整控制和完整设备列表。
- 普通用户对 `Sweetnight-PC` 的最大权限固定为无权限，即使数据库遗留了个人共享规则也不能提升。
- 普通用户不应在客户端发现 `Sweetnight-PC`，直接调用读取或写入接口也返回 403。
- 普通用户仍可完成客户端飞书登录并使用远程桌面；限制仅针对企业地址簿和 API 管理后台。
- API 管理后台飞书 OAuth 完成时再次检查 `is_admin`；普通用户不创建可用的后台会话，并返回 403。

## 界面

- Windows 客户端仅管理员显示地址簿页签；普通用户隐藏入口，状态变化后立即刷新页签。
- API 管理前端的企业地址簿隐藏别名、哈希和 Web Client 展示及操作。
- 地址簿的设备用户名显示 `AddressBook.Username`（飞书昵称），不显示 `Peer.Username`。
- 管理前端仍保留设备管理页的 Windows 系统用户名字段。

## 验证与部署

- 后端：Go 单元测试覆盖普通用户无权限、管理员完整权限、重复登录昵称刷新、后台 OAuth 普通用户拒绝。
- 前端：静态测试覆盖企业地址簿敏感列和 Web Client 按钮不可见；执行 Vite 构建。
- 客户端：Dart 测试覆盖管理员显示、普通用户隐藏；执行相关 Flutter 测试和 Windows 构建前静态检查。
- 部署前备份服务器二进制、配置和管理前端静态资源；部署后校验服务状态、资源校验和、管理员/普通用户权限。
